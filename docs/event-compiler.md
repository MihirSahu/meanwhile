# Structured event compilation

The compiler (now used by the default `scene-reliability-v1` harness) replaces model-written animation commands with sourced event records and a deterministic server compiler. Curated demos, the upstream adapter and the browser's NDJSON protocol are unchanged. `SCENE_MODEL` and compatible reasoning effort remain server configuration; every model stage uses that model.

A normal scene uses five model requests: research, checklist extraction, checklist source review, event plan and complete-scene review. The explicit `startupStrategy: "staged"` evaluation baseline uses the retained legacy harness. The CLI still calls the default strategy `opening` for compatibility; it no longer means an opening-only inference call. There is no automatic fallback to the legacy workflow.

## Records and chronology

The [strict plan schema](../src/lib/server/event-plan.ts) accepts 3–15 records. Each selects one or more frozen claims through a nonempty, duplicate-free array of zero-based indices (`claimIndices`), with a statement, location, participants, kind, template and typed date interval. Multiple records can select different occurrences from one composite claim. The model cannot add claims after freezing. It cannot assign action/entity IDs, timestamps, source URLs/IDs, chapter numbers or requirement deadlines.

Dates contain signed nonzero years, optional months/days, approximation and optional source-supplied zone/calendar labels. The compiler rejects impossible month/day combinations, reversed intervals, dates outside the union of selected claim years (including unsupported gaps) and undated records with event/outcome kinds. Review checks that context/caveat records do not hide dated outcomes. Only context/caveat records may omit dates. February 29 is allowed without asserting a calendar conversion. No time-zone or historical-calendar conversion is performed. Date precision and atomicity still receive source review.

Relations connect event indices with `before`, `overlaps` or `unordered` and fetched passage IDs. The compiler rejects invalid/duplicate pairs, unknown receipts, non-intersecting overlap relations, contradictory date order and cycles. Unambiguous calendar order becomes server-owned edges; sourced before edges can resolve ties at coarse date precision. Overlapping intervals do not impose an order between entire composite claims. Undated context has first priority and undated caveats last, subject to valid relation edges.

[The compiler](../src/lib/server/event-compiler.ts) divides the sorted records into three nonempty chronological groups. Header year bounds cover each group's dated records; a single dated record retains its detailed date label. Undated-only groups use the focus period. Each dated narration includes its own full formatted date. Existing visible-date checks also reject explicit narration dates outside the chapter heading. Required scope cannot be moved to another period merely to fit a chapter.

## Server-owned scene generation

Templates map to prepared assets: place → city, people → uniformed placeholder, battle → static infantry marker, railway → train from 1800 onward (an undated context may use the selected frozen claims’ earliest known year), sailing → sailship, Earth mission → city marker, narration → text-only caption with no Earth position or marker. Named participants use disclosed uniformed placeholders. Template captions explain schematic positions/scale, context anchors, overlapping intervals, illustrative travel stops, comparison order and unavailable spacecraft/lunar assets as applicable. These are presentation restrictions, not historical invention dates or accurate uniforms.

Each event generates a location label, optional participant labels, dated narration and cleanup. The compiler creates stable IDs and maps the selected frozen claims' combined actual passage receipts to registered source IDs. No model copies action-ID proofs or chapter/source mappings. Static templates add no travel paths or attack arrows. Journey records can illustrate selected stops but do not depict a ship's actual course. Lunar events cannot be located on Earth by a mere disclaimer; source review must require an honest Earth-only representation.

Narration slots allow approximately 14 characters per second plus margin; each chapter lasts at least 12 seconds. Longer text increases total duration. The current plan also selects an explicit focus event and can attach visible source qualifications and named relation notes; see [scene reliability](scene-reliability.md). The complete scene passes the same `SceneBuffer` contract before publication, including entity lifecycles, citation equality, action boundaries and final duration. The compiler preserves pause, replay, seeking, speed and cancellation behavior.

## Complete-scene review and publication

[Independent event review](../src/lib/server/event-review.ts) receives frozen claims/passages, exact compiled narration/labels, visible focus metadata and chapter text. Review events remain in original index order with their selected frozen source claims beside them; a separate server-generated index list describes playback order. It checks every event, frozen requirement and relation exactly once by array index. Event/relationship verdicts must cite their own supporting passage basis. Requirements receive candidate event links derived from claim intersection; sharing a claim is not proof that every required concept appears. Full semantic coverage, historical dates and sequence, source interpretation, atomicity and schematic limits must pass review. The compiler supplies explicit structuralValidation receipts for protocol/citation validity and each typed event’s numerical containment in its actual chapter heading. The reviewer treats those structural facts as established, including a year heading containing a precise day; it still checks whether the date itself and the implied historical sequence are supported. Legacy per-claim date checks remain unchanged for the staged baseline. The compiler checks selected date unions before checking rendered text dates, allowing complementary claims without bridging unsourced gaps. Undated records whose known claim ranges all lie outside their chapter are rejected.

The server withholds all playback messages until that review passes. It then emits focus, three batches and `done`. This trades progressive inference for review of a concrete complete story: first-play latency includes whole-story preparation and review. A rejected plan can be repaired once before publication; failure leaves the previous story visible. An interrupted transport may retain already committed batches.

Shared preparation retains one targeted evidence lookup before freezing, two total repairs (one in the legacy staged baseline), input counting, remaining-stage reservations, 16 model calls, 288k observed input tokens, 36k output tokens and the configured deadline. Event-plan output is capped at 6,000 tokens and event review at 3,000. SDK transport retries remain disabled.

## Verification and limits

`npm test`, `npm run typecheck`, `npm run build` and `npm run eval:references` check implementation and contract behavior. New regressions cover chronological splitting of composite claims, overlapping intervals, invalid dates/receipts, cyclic order, deterministic action/citation mappings, readable timing, full review indices, missing requirements, bounded repairs, no publication on review failure and cancellation.

The original event compiler references and audits are recorded in [results](event-compiler-results.md). The multiple-claim and review-calibration milestone is documented in [evidence review](evidence-review.md), with its own [results](evidence-review-results.md). They are withheld from generation. A model can still freeze an overstated claim, misinterpret a source, bundle events or misjudge coverage; deterministic compilation does not certify history. The source and event reviews are separate calls to the same configured model. Independent human historical review remains pending. Earlier milestone results remain historical cohorts and are not rewritten or pooled into this run.
