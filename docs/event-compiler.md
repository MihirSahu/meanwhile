# Structured event compilation

The compiler (now used by the default `discovery-evidence-v1` harness) replaces model-written animation commands with sourced event records and a deterministic server compiler. Curated demos, the upstream adapter and the browser's NDJSON protocol are unchanged. `SCENE_MODEL` and compatible reasoning effort remain server configuration; every model stage uses that model.

A normal scene uses five model requests: research, checklist extraction, checklist source review, event plan and complete-scene review. The explicit `startupStrategy: "staged"` evaluation baseline uses the retained legacy harness. The CLI still calls the default strategy `opening` for compatibility; it no longer means an opening-only inference call. There is no automatic fallback to the legacy workflow.

## Records and chronology

The [strict plan schema](../src/lib/server/event-plan.ts) accepts 3–18 records. Each selects one or more frozen claims through a nonempty, duplicate-free array of zero-based indices (`claimIndices`), with a statement, location, participants, kind, template and typed date interval. Multiple records can select different occurrences from one composite claim. The model cannot add claims after freezing. It cannot assign action/entity IDs, timestamps, source URLs/IDs, chapter numbers or requirement deadlines.

Checklists can hold eighteen compact claims so a dated occurrence can be separated from an undated assertion without discarding essential scope. Before freezing, recognized explicit dates in claim text cannot have `yearRange: null`; quantity counts and genuinely undated context remain allowed. Year bounds do not require month/day precision. Extraction and source review are instructed to split facts with different temporal support and update requirement links. The planner receives explicit dated/undated claim-index lists, and both normal planning and constrained date repair support all eighteen indices. Undated complementary facts still cannot supply a dated event's year bounds. The final plan remains limited to eighteen records, with at most eight selected claims per record. Call/token budgets and the eight-requirement limit are unchanged.

Dates contain signed nonzero years, optional months/days, approximation and optional source-supplied zone/calendar labels. The compiler rejects impossible month/day combinations, reversed intervals, dates outside the union of selected claim years (including unsupported gaps) and undated event records. Context/caveat records may omit dates; genuinely undated outcomes may also omit dates when a sourced before chain places them after a dated occurrence. Their narration says “Undated aftermath” and chapter captions distinguish them from the calendar heading. Review checks the anchor, subsequent duration and source support, and rejects hiding available dates or relabeling later outcomes as introductory context. February 29 is allowed without asserting a calendar conversion. No time-zone or historical-calendar conversion is performed. Date precision and atomicity still receive source review.

A missing required date, missing aftermath anchor or date outside the selected claim-year ranges produces a structured rejection identifying the event, requested date, and selected frozen claim bounds. Its repair uses a separate strict schema with only a non-null date and claim indices, or an evidence clarification. For an outcome that was already undated, a second strict variant can instead add one sourced before relation to an existing anchor; it cannot change the outcome into context, rewrite actors or remove a previously supplied date. The server applies that patch to the original occurrence without rewriting its kind, title, statement, participants, location, or other events, then recompiles and source-reviews the complete story. This prevents the reported repair from turning a dated wartime outcome into undated introductory context. Genuine undated context in an initial plan retains its existing contract. Repair count and budget limits are unchanged. This path is verified with offline compiler/harness, strict-schema and cancellation regressions; the subsequent live debugging session is recorded in [custom-prompt verification](custom-prompt-verification.md).

Relations connect event indices with `before`, `overlaps` or `unordered` and fetched passage IDs. The compiler rejects invalid/duplicate pairs, unknown receipts, non-intersecting overlap relations, contradictory date order and cycles. Unambiguous calendar order becomes server-owned edges; sourced before edges can resolve ties at coarse date precision. Overlapping intervals do not impose an order between entire composite claims. For overlapping or coarse intervals with no enforced order, the compiler preserves the proposed event-array order. It does not treat a year-only date as January 1, prepend undated context, or append all caveats automatically. The planner must propose a sourced narrative sequence and the final reviewer checks the actual playback order.

[The compiler](../src/lib/server/event-compiler.ts) divides the sorted records into three nonempty chronological groups. Header year bounds cover each group's dated records; a single dated record retains its detailed date label. Undated-only groups use the focus period. Each dated narration includes its own full formatted date. Existing visible-date checks also reject explicit narration dates outside the chapter heading. Required scope cannot be moved to another period merely to fit a chapter.

## Server-owned scene generation

Templates map to prepared assets: place → city, people → uniformed placeholder, battle → static infantry marker, railway → train from 1800 onward (an undated context may use the selected frozen claims’ earliest known year), sailing → sailship, Earth mission → city marker, narration → text-only caption with no Earth position or marker. Named participants use disclosed uniformed placeholders. Role phrases permit up to eighty characters; a combined name/role exceeding the eighty-character map-label limit is shown as a separately timed, cited note while the marker keeps the complete name. Text is not clipped. Template captions explain schematic positions/scale, context anchors, overlapping intervals, illustrative travel stops, comparison order and unavailable spacecraft/lunar assets as applicable. These are presentation restrictions, not historical invention dates or accurate uniforms.

Each event generates a location label, optional participant labels, dated narration and cleanup. The compiler creates stable IDs and maps the selected frozen claims' combined actual passage receipts to registered source IDs. No model copies action-ID proofs or chapter/source mappings. Static templates add no travel paths or attack arrows. Journey records can illustrate selected stops but do not depict a ship's actual course. Lunar events cannot be located on Earth by a mere disclaimer; source review must require an honest Earth-only representation.

Narration slots allow approximately 14 characters per second plus margin; each chapter lasts at least 12 seconds. Longer text increases total duration. The current plan also selects an explicit focus event and can attach visible source qualifications and named relation notes; see [scene reliability](scene-reliability.md). The complete scene passes the same `SceneBuffer` contract before publication, including entity lifecycles, citation equality, action boundaries and final duration. The compiler preserves pause, replay, seeking, speed and cancellation behavior.

Semantic corrections use [indexed edits](../src/lib/server/event-repair.ts), preserving untouched records and existing date presence. An event/context correction can change between those two kinds; outcomes and caveats cannot become introductory context. Repairs may remove optional records or append split records. Intermediate indices can address eighteen originals plus twelve additions; the final plan must still contain three to eighteen records. The server remaps focus and relations after removals/reordering, and rejects dangling references. Null order retains every surviving record automatically. Every patched scene is compiled and independently reviewed again. Distinct follow-up semantic findings may use a second event repair; an identical unresolved finding stops.

Story scope and the initial camera anchor are separate. A worldwide story can display a worldwide scope label while centering on a sourced mapped event. Review receives both fields and still requires a localized story's anchor to match its main site.

## Complete-scene review and publication

[Independent event review](../src/lib/server/event-review.ts) receives frozen claims/passages, exact compiled narration/labels, visible focus metadata and chapter text. Review events remain in original index order with their selected frozen source claims beside them; a separate server-generated index list describes playback order. It checks every event, frozen requirement and relation exactly once by array index. Event/relationship verdicts must cite their own supporting passage basis. Requirements receive candidate event links derived from claim intersection; sharing a claim is not proof that every required concept appears. Full semantic coverage, historical dates and sequence, source interpretation, atomicity and schematic limits must pass review. The compiler supplies explicit structuralValidation receipts for protocol/citation validity and each typed event’s numerical containment in its actual chapter heading. The reviewer treats those structural facts as established, including a year heading containing a precise day; it still checks whether the date itself and the implied historical sequence are supported. Legacy per-claim date checks remain unchanged for the staged baseline. The compiler checks selected date unions before checking rendered text dates, allowing complementary claims without bridging unsourced gaps. Undated records whose known claim ranges all lie outside their chapter are rejected.

The server withholds all playback messages until that review passes. It then emits focus, three batches and `done`. This trades progressive inference for review of a concrete complete story: first-play latency includes whole-story preparation and review. A rejected plan can use the remaining event repair allowance before publication; failure leaves the previous story visible. An interrupted transport may retain already committed batches.

Shared preparation permits two focused document rereads and at most two targeted searches for distinct missing evidence, including a late planner gap before publication. A fresh provider using cached receipts may refetch their registered pages for rereading. Evidence changes rebuild and source-review the checklist, retaining coverage questions; only source-reviewed preparation is cached. A failed coverage check evicts the weak cache entry. Internal source questions remain in terminal diagnostics rather than asking the visitor to perform research.

The default workflow permits two checklist repairs and two event repairs. One additional capacity replan can shorten a proposal within the fixed limit; it retains the latest event review and does not consume a factual repair or trigger research. The legacy staged baseline retains one shared repair and one targeted search. All optional work remains subject to input counting, remaining-stage reservations, sixteen model calls, 288k observed input tokens, 36k output tokens and the configured deadline. Event-plan output is capped at 6,000 tokens and event review at 3,000. SDK transport retries remain disabled. See [world-war recovery](world-war-recovery.md) for live observations and remaining limits.

## Verification and limits

`sfw pnpm test`, `sfw pnpm typecheck`, `sfw pnpm build` and `sfw pnpm eval:references` check implementation and contract behavior. New regressions cover chronological splitting of composite claims, overlapping intervals, invalid dates/receipts, cyclic order, deterministic action/citation mappings, readable timing, full review indices, missing requirements, bounded repairs, no publication on review failure and cancellation.

The original event compiler references and audits are recorded in [results](event-compiler-results.md). The multiple-claim and review-calibration milestone is documented in [evidence review](evidence-review.md), with its own [results](evidence-review-results.md). They are withheld from generation. A model can still freeze an overstated claim, misinterpret a source, bundle events or misjudge coverage; deterministic compilation does not certify history. The source and event reviews are separate calls to the same configured model. Independent human historical review remains pending. Earlier milestone results remain historical cohorts and are not rewritten or pooled into this run.
